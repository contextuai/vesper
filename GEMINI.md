# GEMINI.md — Vesper Workspace Rules

Project rules for **Vesper** (`https://github.com/contextuai/vesper`). Read `CLAUDE.md` in this repository for full architecture, commands, and subsystem details.

## Project Identity & Runtime Defaults
- **Product**: **Vesper** (`contextuai/vesper`), a local-first AI desktop app (Tauri v2 + React 19 + FastAPI sidecar).
- **Default edition**: `lite` (`CONTEXTUAI_EDITION="lite"`, `VITE_APP_EDITION="lite"`).
- **Fixed ports**: Vite frontend dev server on `1420`, FastAPI backend sidecar on `18741`.

## Git & Branch Protection Rules
- `main` is branch-protected (`Build & Type Check` and `Playwright E2E` required via PR; `enforce_admins: true`).
- **Never** commit or push directly to `main`. Always work on a topic branch (`feat/*`, `fix/*`, `docs/*`, `chore/*`) and open a PR.
- **Never** merge a PR or run irreversible remote release actions without explicit user confirmation.

## Mandatory Release Workflow
- Merging feature/fix/docs PRs (`feat:`, `fix:`, `docs:`) does **not** build a release — `.github/workflows/release.yml` intentionally skips non-release commits.
- When preparing a release (after release changes are merged, or when asked to cut a release):
  1. Validate the target version matches strict MSI-safe semver `^\d+\.\d+\.\d+(-\d+)?$` (never alphanumeric prereleases like `-beta.3`).
  2. Branch `chore/release-vX.Y.Z` from updated `origin/main`.
  3. Bump **all 4 version files** in sync — and **do not** edit `frontend/package-lock.json` or `frontend/src-tauri/Cargo.lock`:
     - `frontend/package.json` (`"version"`)
     - `frontend/src-tauri/tauri.conf.json` (`"version"`)
     - `frontend/src-tauri/Cargo.toml` (`version = "..."` under `[package]`)
     - `frontend/src-tauri/tauri.lite.conf.json` (`"version"`)
  4. Commit (`chore: release vX.Y.Z`) and open a PR with the **exact title `chore: release vX.Y.Z`** (so squash-merge creates `chore: release vX.Y.Z (#NNN)`, matching `release.yml`'s strict regex).
  5. Wait for all PR checks (`Build & Type Check`, `Backend Unit Tests (pytest)`, `Playwright E2E`) to pass, then ask the user for confirmation before squash-merging (`gh pr merge <pr#> --squash`).
  6. Never manually `git tag` or `git push` tags; `release.yml` automatically creates the tag via GitHub REST API, builds installers, publishes the GitHub Release, and generates `latest.json` (including only platforms with uploaded updater assets). Verify both the release workflow and live `latest.json` assets after merge.

## Living Model Catalog
- The daily OTA model catalog (`https://contextuai.github.io/vesper/models.json`) is generated by `backend/scripts/sync_catalog_json.py` and deployed to **GitHub Pages** by `.github/workflows/sync-model-catalog.yml` (never `git push` to `main`).
